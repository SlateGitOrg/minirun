# Decisions

Rulings made while building minirun, in the format
`Ruling: <what> — <why> — <cost if wrong>`.

- Ruling: compile seccomp profiles to classic BPF in pure Go instead of linking libseccomp — keeps the binary static and cgo-free, and lets the compiler be verified on macOS against a reference evaluator through a seccomp-faithful interpreter — the compiler has none of libseccomp's field history; a semantic mismatch on an edge case (rule ordering, x32) would silently weaken or break a profile.
- Ruling: dispatch with a balanced binary search over merged syscall-number ranges, not a linear jeq chain — O(log R) instructions per syscall (measured avg 11 vs 187 for the default profile) at the cost of a label assembler with trampoline relaxation — a bug in relaxation would produce wrong jump offsets; mitigated by kernel-rule validation of every program and the property/fuzz tests.
- Ruling: define profile semantics as "conditional rules in profile order, then the single unconditional rule, then the default" and reject conflicting unconditional rules — deterministic and easy to state; libseccomp orders rules by its own priority — profiles that rely on libseccomp's ordering for overlapping conditional rules may behave differently.
- Ruling: kill calls from a foreign architecture (and x32 calls on x86-64) with KILL_PROCESS, and accept only SCMP_ARCH_X86_64/AARCH64 tables — the runtime only runs native binaries of those two ABIs; 32-bit compat calls are an attack surface with no use case here — 32-bit binaries inside containers will not run.
- Ruling: model the default allow-list on Docker's default profile (no CAP_SYS_ADMIN variant), dropping 32-bit-only names, denying clone with namespace flags, clone3 with ENOSYS and AF_VSOCK sockets — a widely exercised baseline that ordinary software works under — Docker's capability-conditional sections are flattened; e.g. chroot is always allowed.
- Ruling: build a validated launch plan in the parent and keep the child a plan executor — one place for validation, `minirun plan` shows the exact sequence on any OS, and the child carries no decision logic — the plan format is an internal contract between two copies of the same binary; it is not versioned.
- Ruling: re-execute the binary (`__init`/`__exec`) rather than use a cgo constructor — no cgo, one static binary — Go cannot setns into a user namespace from a multithreaded process, so exec into user-namespaced containers is refused.
- Ruling: refuse `exec` into containers with a user namespace instead of running the process with host-mapped credentials outside that namespace — a process outside the container's user namespace would have capabilities interpreted in the host namespace, an isolation downgrade — users of --userns cannot exec.
- Ruling: lock the init/exec helper to one OS thread from `main.init`, set GOMAXPROCS(1), and change identity with raw per-thread syscalls before execve from the same thread — capabilities, credentials and seccomp are per-thread; Go's syscall.Setuid broadcasts to all threads — relies on execve discarding the other (still privileged) Go threads, which it does.
- Ruling: join the container cgroup late (parent writes the pid to cgroup.procs right before releasing the child), not via clone3 CLONE_INTO_CGROUP — the Go runtime's threads would otherwise count against pids.max (integration uses pids.max=8) and migration is never refused by the pids controller — setup work (mounts) is not charged to the container's cgroup.
- Ruling: overlayfs is mandatory (bundle rootfs as read-only lower, upper/work in the state dir) and the state dir must accept an overlay upper layer — keeps bundles pristine and makes `delete` a directory removal — the state dir cannot live on overlayfs (e.g. inside a Docker container without a tmpfs), which the error message now explains.
- Ruling: default rootfsPropagation is rprivate — no mount events leak in either direction — configs needing slave propagation must ask for it.
- Ruling: bind-mount host device nodes into a tmpfs /dev instead of mknod — works the same with and without a user namespace — device numbers are the host's (fine for null/zero/random).
- Ruling: tolerate unknown config keys and report them as warnings — configs from `runc spec` should load; silently ignoring them would mislead — a key the user relies on for security (apparmorProfile) is not enforced, only reported.
- Ruling: reject runc-style ambient capabilities that are not also inheritable, instead of ignoring the failed raise — PR_CAP_AMBIENT_RAISE would fail anyway; a config error is clearer than a runtime EPERM or a silent drop — `runc spec` output from older runc versions needs its ambient list removed.
- Ruling: permitted must lie inside the bounding set (policy, not a kernel rule) — a config that drops a capability from the bounding set but keeps it permitted is almost certainly a mistake — unusual but legal configs are rejected.
- Ruling: execute helpers from a write-sealed memfd copy of /proc/self/exe — closes the CVE-2019-5736 class for the window in which the helper is visible in the container's pid namespace — costs one binary copy (a few MB) per launcher and requires memfd exec (blocked if vm.memfd_noexec=2).
- Ruling: detached containers have no supervisor; status is derived from /proc with a pid + start-time check — keeps the process model to one parent and one child — exit codes of detached containers are not recorded.
- Ruling: state removal refuses to cross mount points — RemoveAll through a leaked bind mount would delete host data — a leaked mount must be unmounted by hand before delete succeeds.
- Ruling: Linux signal numbers are parsed from a table in the signals package instead of syscall constants — the CLI must behave identically when built on macOS, whose numbers differ — the table must be kept in sync with the kernel (it has been stable for decades).
- Ruling: the integration suite runs in a privileged Docker container built from the official Alpine minirootfs (docker import, checksum-verified), mounts a tmpfs for the state dir and moves its own processes into a leaf cgroup before starting — no third-party image pull, and those two steps are exactly what a host would provide — results are from Docker Desktop's linuxkit kernel, not a stock distribution kernel.
- Ruling: core-logic coverage excludes `*_linux.go` kernel glue and the floor is 85% — that glue cannot run in an unprivileged unit test and is exercised by the 46 integration assertions instead; both numbers are printed — a unit-coverage figure says nothing about the glue.
- Ruling: generated syscall tables come from golang.org/x/sys's zsysnum files (pinned module version) rather than kernel headers — reproducible offline from the module cache with `make tables` — tables lag the newest kernels by whatever x/sys lags.
